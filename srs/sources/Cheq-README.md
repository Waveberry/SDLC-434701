# Cheq 0.9 — исходники следующей сборки

Изменения от 28.10.2026: подключение через Cloudflare Workers и единая мягкая тень плашек без двойной тени диалогов. APK ещё не собран; Worker опубликован и секреты настроены, но Groq отвечает403, поэтому приложение не переключено на этот маршрут. Запуск и проверки описаны в [docs/workers.md](docs/workers.md).

Нативное Android-приложение на **Java 17 + XML**, папка проекта: `D:\VS Code\Cheq`.

## Запуск в Windows / VS Code

Открой папку проекта в VS Code и нажми **Ctrl+Shift+B**. Либо выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

APK появится в `app\build\outputs\apk\debug\Cheq.apk`. Поддерживается только ARM64 (`arm64-v8a`), Android 8+; установи его или подключи телефон с разрешённой отладкой по USB:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Install
```

Пакет приложения: **com.waveberry.cheq**, название: **Cheq**. Из-за смены пакета приложение установится отдельно от прежнего ReceiptBox (com.receiptbox); его данные автоматически не переносятся. Обновления внутри нового пакета сохраняют покупки; база поддерживает миграции v1/v2/v3/v4 → v5 с сохранёнными курсами, бюджетами и картами.

Проверки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Check
```

JDK 17 установлен в `C:\Program Files\Java\jdk-17.0.20.1+1`; скрипт выбирает его сам. Android Studio не нужна. SDK настроен через исключённый из Git `local.properties`, текущий путь — `.tools\android-sdk`. На другом компьютере установи JDK 17 и Android Command-line Tools и выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -ToolsPath 'C:\Program Files\Android SDK\cmdline-tools\bin'
```

Первое скачивание зависимостей требует сети. Сохранённые данные и ручное добавление работают офлайн; импортированные чеки ожидают сети для анализа Groq. В проекте нет Kotlin-файлов и Kotlin-плагина; AndroidX может использовать Kotlin runtime внутри.

## Новый интерфейс

- Светлая, тёмная и системная темы. Тёмная тема использует чёрный фон и графитовые панели.
- Снизу компактная плавающая капсула: **Покупки, Товары, Расходы, Настройки**; кнопки одинаковой ширины. Под ней градиент от прозрачного к фону, сверху — обратный.
- Названий экранов сверху нет; остаются поиск и «Ещё». В меню доступны **Представление** и **Сортировка**; всплывающее меню подгоняется под текст и появляется от кнопки. Подтверждения и выбор параметров открываются снизу на доступную ширину с полями 12dp. Меню, диалоги, верхняя и нижняя капсулы размывают содержимое под собой; текст и значки остаются резкими. Фиолетовой подложки и нарисованного градиента на плашках нет.
- Покупки отображаются карточками в два столбца или списком. На карточке только фото, магазин и сумма, без количества товаров и повторной даты; группировка «Сегодня», «Вчера», по датам.
- Поиск по магазину, названиям товаров и дате; представление и сортировка сохраняются. Поиск корректно восстанавливается при повороте.
- Шрифт Roboto с кириллицей встроен в приложение; контурные иконки Lucide. Иконка запуска — оригинал пользователя cheqicon.png. Это подобранный по референсам стиль, точное совпадение с неизвестным шрифтом Samsung не заявляется.

**Добавить чек → камера / фото / вручную → проверить → сохранить.** В товарах — история цен, независимые представление «Карточки/Список» и сортировка по дате, имени или цене; в расходах — месяцы, категории и бюджет; в настройках — тема, общая валюта, месячный лимит, банковские карты. Groq используется автоматически, отдельного переключателя нет. Поиск и меню при открытии настроек плавно исчезают; верхние заголовки жирные.

Настройки собраны в округлые группы; у нижних диалогов текстовые кнопки с разделителем. Верхнее затемнение остаётся и в настройках. Сохранённый чек прокручивается внутри нижней панели, включая длинный список товаров. Товары сгруппированы по категориям.

При ручном добавлении сначала доступны компактные строки товаров; цена за единицу/кг раскрывается отдельно. Магазин необязателен, итог автоматически складывается из сумм строк, а сохранение и итог закреплены внизу. Итог можно задать вручную и затем вернуть автоматический расчёт. Исходный текст сворачивается; у распознанного чека напечатанный итог сохраняется отдельно от суммы товаров и не заменяется автоматическим расчётом.

## Выбор нескольких покупок и товаров

Удержи покупку или товар: появятся кружки выбора, счётчик, «Все» и «Отмена». Нажатие на заголовок даты или категории выбирает всю видимую группу; «Все» работает по текущему списку с учётом поиска. Выбор сохраняется при повороте; «Назад» и «Отмена» завершают режим.

Нижняя навигация на время выбора заменяется действиями: у покупок — **Карта, Поделиться, Удалить**, у товаров — **Категория, Поделиться**. Карта назначается выбранным покупкам, категория — всем сохранённым строкам выбранных товаров. Массовые изменения выполняются транзакцией. Удаление покупок требует подтверждения, удаляет их строки и удаляет фото только после исчезновения последней ссылки на него.

«Поделиться» создаёт UTF-8 TXT: для покупок — магазин, дата, позиции и итог; для товаров — категория и история цен в исходных валютах. Файл передаётся через Android FileProvider с временным разрешением чтения, без исходного OCR-текста, фотографий и данных банковских карт. Это выборочный текстовый экспорт, не резервная копия. Подробности: [docs/selection-0.6.md](docs/selection-0.6.md).

Электронные чеки также поддерживаются: Google Play, App Store, Steam и другие покупки приложений/игр. Категории **Подписки**, **Приложения**, **Игры** доступны автоматически и вручную. Для подписки извлекаются название покупки и оплаченная сумма; дата следующего продления не заменяет дату заказа. Это учёт совершённых покупок, без планировщика будущих списаний. Для бледных скриншотов локальный OCR при необходимости усиливает контраст; оригинальное фото сохраняется без изменений.

## Общая валюта и бюджет

Все покупки отображаются вместе без фильтра валют. Исходные сумма и валюта остаются на карточке и в чеке. В настройках можно выбрать общую валюту BYN, RUB, EUR, USD, KZT или PLN. Расходы и сортировка сумм пересчитываются в неё по официальному курсу [Нацбанка Беларуси](https://www.nbrb.by/apihelp/exrates) **на дату каждой покупки**, с учётом масштаба котировки (например, за 100 RUB). Для двух иностранных валют используется точный кросс-курс через BYN; сумма округляется до копейки один раз, без вычислений с плавающей точкой.

Курсы загружаются в фоне и сохраняются на устройстве; повторный расчёт доступен без сети. Если курса ещё нет, покупка сохраняется, а расходы явно показывают ожидание курса или частичную сумму со знаком `*`; чужая валюта не считается нулём и не пересчитывается по сегодняшнему курсу. После восстановления сети загрузка повторяется автоматически. В подробностях чека видны дата курса и сумма в общей валюте.

Бюджет задаётся в настройках для выбранного месяца и общей валюты; 0 или пустое поле означает отсутствие лимита. В расходах показываются лимит, остаток либо превышение и прогресс. При недостающих курсах остаток не выдаётся за окончательный. Лимиты разных месяцев и валют сохраняются отдельно.

При расходе от 80% лимита индикатор становится янтарным, при превышении 100% — красным. При запуске приложение сообщает о приближении к лимиту либо превышении; при неполных курсах уведомление ждёт полного расчёта.

## Банковские карты

В настройках можно добавить название карты и последние четыре цифры, изменить или удалить запись. Полный номер, срок действия и CVV не запрашиваются. Groq теперь возвращает последние четыре цифры отдельным полем: приложение сверяет их с исходным текстом и выбирает единственную подходящую карту. Если такой карты ещё нет, создаётся запись «Карта · •• 2468»; при одинаковых цифрах у нескольких карт требуется ручной выбор. Локальное определение по маске тоже сохранено. Ручная карта и явное «Без карты» имеют приоритет над Groq и переживают поворот. При изменении текста прежняя автоматическая привязка очищается. Удаление карты оставляет покупки без этой связи.

В расходах есть раздел **По картам**: сумма и количество покупок за выбранный месяц, группа **Без карты**, явное ожидание недостающих курсов. Нажатие на карту открывает список её покупок с датами и исходными валютами. Суммы пересчитываются в общую валюту по историческому курсу; это учёт внесённых покупок, без подключения к банковскому счёту.

В настройках поля совпадают с фоном группы, а «Сохранить» находится справа от суммы бюджета. Выбор темы и валюты не фильтруется при восстановлении экрана: после смены темы остаются все варианты.

Фото чека теперь хранится в приватной папке приложения. Открытие карточки показывает фото и позиции; удаление покупки удаляет фото, когда оно больше не используется. Восстановить фотографии старых чеков нельзя: версия 0.1 удаляла их после OCR. Чеки без фото показываются с иконкой.

## Groq встроен по прямому указанию пользователя

Положи **GroqApi.key** в корень проекта: файл должен содержать только ключ. При сборке Gradle помещает его в генерируемый asset; телефон обращается к Groq напрямую по HTTPS. Запуск Java-сервера, токены сервера и `adb reverse` больше не нужны.

**Ключ находится в APK и может быть извлечён из него.** Это сознательное изменение предыдущей архитектуры по запросу пользователя; сокрытие файла внутри сборки не делает ключ защищённым. Не публикуй такую сборку как приложение с общим секретным ключом.

`*.key`, `.env`, SDK/JDK, build-assets и `local.properties` исключены из Git и архива исходников. Поэтому при сборке из архива свой ключ нужно положить отдельно. Без ключа работают локальные функции; облачный разбор будет недоступен.

Фото сначала сохраняется в личной очереди приложения. ML Kit и Tesseract читают текст на телефоне; товары определяет только Groq, локальный разбор товаров больше не используется как резерв. Без подтверждённого интернета карточка показывает ожидание; при восстановлении связи или следующем открытии приложения очередь продолжает работу. Ошибка403 не выдаётся за отсутствие интернета: чек остаётся в очереди с сообщением о недоступности Groq. После анализа нужно проверить и сохранить покупку; ожидающие и непроверенные чеки не включаются в расходы, бюджет и каталог товаров.

Очередь переживает завершение процесса, хранит отдельные фото и черновики, не затирает ручной черновик. Повторное сохранение одного ожидающего чека блокируется транзакционной отметкой в базеv5. Отправляется только OCR-текст без фото и внутренних идентификаторов карт; модель `openai/gpt-oss-20b` возвращает строгую JSON-схему, проверяемую на телефоне.

Папка `proxy` и `scripts/proxy.ps1` оставлены как отдельный альтернативный серверный прототип предыдущей версии; текущее Android-приложение их не использует.

## Данные и ограничения

- Локальные OCR-модели встроены: ML Kit Latin и Tesseract rus+eng всегда работают вместе. Строки объединяются по расположению без дублирования товаров и потери кириллицы. При отказе одного движка остаётся результат второго; после установки загрузка моделей не требуется.
- Покупки, товары, фото, карты, бюджет и статистика доступны без интернета. Для пересчёта иностранных валют офлайн нужен ранее сохранённый исторический курс.
- У распознанных весовых товаров сохраняется исходная цена за единицу/кг; её можно проверить и исправить. Если цену при ручном вводе оставить пустой, она вычисляется из суммы и количества.
- OCR и нейросеть могут ошибаться; перед сохранением нужно проверить чек. Общая скидка без распределения по строкам показывается как расхождение сумм в редакторе; значения не переписываются ради искусственного совпадения.
- Полная резервная копия, синхронизация, автоматическое объединение разных сокращений и перевод кг/г не реализованы. Доступен выборочный TXT-экспорт через «Поделиться». Удаление приложения удаляет его данные; резервное копирование отключено.
- Сборка debug предназначена для установки и проверки, не для публикации. Камера и OCR на физическом устройстве в этой среде не проверены.

Фактические проверки: `docs/verification.md`. PNG-превью получены рендером настоящих XML в Robolectric Native Graphics с искусственными чеками; это не снимки телефона.
В расходах сумма и количество покупок находятся в верхней строке рядом с поиском и меню. Кнопка BYN и строка стрелок убраны; нажми на строку с количеством и месяцем для выбора периода снизу.

## Очистка после сборки

Сначала сохрани готовый APK и, при необходимости, архив исходников вне удаляемых каталогов и проверь их. После завершения сборки и остановки Gradle можно удалить только восстанавливаемые файлы проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\cleanup-generated.ps1 -OutputApk 'C:\путь\к\Cheq.apk' -SourceZip 'C:\путь\к\Cheq-source.zip' -WhatIf
```

`-WhatIf` показывает объём без удаления; после проверки убери этот параметр. `-SourceZip` необязателен; каждый переданный файл должен существовать и быть непустым. Скрипт рассчитан на `D:\VS Code\Cheq`: удаляет только `.gradle`, `build`, `app\build`, `core\build`, `proxy\build`, `work`; отклоняет ссылки и junctions и проверяет, что готовые файлы не лежат внутри удаляемых каталогов. Исходники, `.tools` с Android SDK, ключ, `local.properties`, Git и системная Java сохраняются. Кеши сборки и превью будут созданы заново следующей сборкой и проверками.

## Проверка извлечения 0.8

Переводы и платёжные квитанции без состава сохраняются одной суммой **без товаров**: итог, комиссия и сумма перевода не дублируются в каталоге. Для перевода используется карта списания, а не карта получателя. Неизвестная категория — «Другое», без подстановки продуктов/напитков. Если товары не прочитаны, можно сохранить положительный итог и позже добавить состав.

Автоматические проверки включают разнообразные синтетические тексты чеков и регрессии для весов, отдельных строк цен, скидок, налогов, оплаты, подписок, услуг и переводов. Отдельный проверочный сценарий `scripts/verify-receipt-corpus.ps1` отправляет синтетические документы в Groq; пользовательские фото в облако тестами не отправляются. Исходное изображение банковского перевода проверено локальным Tesseract с моделями rus/eng; это проверка настольного OCR, не запуск на физическом телефоне.

## Уменьшение размера и текущая проверка

Оставлена только ARM64; в release включены R8 и удаление неиспользуемых ресурсов с сохранением JNI/OCR и конструкторов ViewModel. По составу существующей APK82,02МиБ исключение остальных архитектур даёт оценку около33,03МиБ до дополнительного сжатия release. Новая APK не собиралась; фактический размер ещё не измерен. См. [docs/apk-size.md](docs/apk-size.md).

Тесты и инструменты сохранены: в основной APK они не входят. Исходники очереди и интерфейса проверены синтаксическим разбором Java без анализа типов/генерации классов, ресурсы — разбором XML; runtime-проверка новой Android-версии не выполнялась из-за запрета сборки. Действующий Worker по последней сетевой проверке по-прежнему получает403 от Groq, поэтому успешный облачный анализ в реальной сети не подтверждён.
